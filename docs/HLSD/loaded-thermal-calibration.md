# Thermal response under printing load

The loaded calibration uses a native Orca-sliced continuous spiral fixture and an internal Moonraker worker launched by Calibration > Hotend thermal response. The slicer's adaptive-temperature option is disabled in the fixture. A baseline nominal flow of 10 mm3/s is scaled with M220; live commanded extruder velocity, multiplied by the known filament cross-section, checks whether the requested load has been established. This observes a commanded extrusion rate, not melt flow, missed steps or extrudate temperature.

The controller requires explicit execution, an exact active calibration filename and an unpaused print. A one-time M400 before the seventh layer, layer-statistics markers, both print-statistics and virtual-SD layer counters, live Z and fan state distinguish the measurement region from startup/purge and first layers. After verifying the exact active fixture the controller initializes TOTAL_LAYER from the virtual-SD layer count. It never synthesizes CURRENT_LAYER; the synchronized fixture markers remain authoritative. This accommodates K2PRO firmware that ignores CURRENT_LAYER updates before TOTAL_LAYER is initialized. The one-time synchronization lies outside the measured region. Temperature control during measurement uses non-waiting M104 and speed scaling; it inserts no waiting moves or pauses between stages.

The supplied PLA table constrains the protocol. Thermal target steps are evaluated at fixed low or medium load, while high-load transitions use the high-load target. The controller never requests 196 or 213 C at 22 mm3/s. Constant-target load transitions are reported separately from temperature-step response fits.

Progress requires ten continuous seconds inside a one-degree target band, a five-second time-weighted mean commanded flow within ten percent of the requested flow, and positive ongoing extrusion. Excursions reset the dwell. A stationary hot nozzle cannot qualify. A sampling gap, clock reversal, retraction, unexpected target, changed fan conditions or unexpected extrusion multiplier invalidates the running experiment. Per-stage and overall timeouts are failure bounds, not fixed dwell durations. An interrupted load is excluded from a target-step fit even if it subsequently settles.

A successful stage records its elapsed/settling time. Complete target crossings at ten and ninety percent provide a descriptive seconds-per-degree slope and an extrapolated nonnegative delay at the recorded load. This is not a universal hotend model and does not automatically change printer profiles or constrain ordinary printing speeds.

Raw CSV retains target, sensor, power, all relevant fan states, bed temperature, stage identity and commanded flow. The constant-deposition field is intentionally empty, preventing the simpler CSV importer from treating variable commanded extrusion as a precise constant deposited flow. The native importer independently analyzes the CSV by contiguous stage names. Each temperature step gets its own preceding baseline and subsequent plateau; later load changes cannot contaminate it. All three recorded fan channels and commanded flow qualify fixed-load responses. The original constant-deposition field remains empty and separate. JSON summaries are retained for provenance, but the GUI does not trust them as measurement evidence. Heating/cooling settling time per degree and observed delay are provisional planning references, shown separately from the 10-90% sensor slope. They remain distinct from the provisional target-ramp proposals described in [thermal response](hotend-thermal-response.md); application and saving are explicit user actions.

On completion or failure the controller rechecks calibration job identity, attempts to restore the speed override, and invokes normal cancellation for that job. It never uploads or starts a file, installs firmware macros, or cancels a differently named job. A cancellation HTTP timeout does not trigger a duplicate cancel. Bounded status polling independently confirms the same job is cancelled, virtual SD is inactive, both heater targets are zero and the speed multiplier is restored. Measurement completion and cancellation confirmation are separate summary fields. Identity changes abort confirmation without controlling the replacement job. Network failure can prevent confirmation of cancellation, so printer supervision remains necessary. Offline numerical and mocked API tests do not establish physical printing performance.


The calibration dialog exports the supplied K2PRO PLA fixture with its original filename; transfer and print start remain explicit actions in the printer interface. Its fixed 196/213/228 C and 1/10/22 mm3/s protocol is displayed before recording and is independent of the selected filament table. The operator acknowledges the printer, filament, nozzle and bed conditions before starting. This fixture is not a general-purpose calibration generator for arbitrary printers or materials.

The GUI launches the worker with the bundled Python interpreter and an argument vector, without a command shell or visible terminal. It verifies the uploaded G-code SHA-256 before issuing any printer control. The worker uses only the Python standard library; canonical sources live under scripts and CMake stages runtime copies in resources/calibration. Raw CSV, summary, worker log and progress files use a new recording name. Existing recordings are not replaced. The native CSV analyzer is shared between imported files and the recording workflow; applying and saving settings remain explicit.

A timer refreshes an owner heartbeat while the asynchronous worker performs HTTP requests. Stop writes a cooperative cancellation request, and normal dialog close waits for the worker's guarded cleanup. Forced shutdown leaves the worker alive to clean up; an expired heartbeat also requests cleanup after fifteen seconds without refresh. The GUI never kills the worker to stop a measurement. Network timeouts and cancellation confirmation happen in the worker, keeping the UI responsive. Stop does not merely end logging: it cancels the verified calibration print. A failed cancellation is distinguished from an intentionally stopped, confirmed experiment; the partial CSV remains available for inspection. A heartbeat and mocked tests cannot guarantee cancellation after operating-system shutdown or loss of printer connectivity.

The public prepared fixture omits the embedded printer/process/filament configuration block and supplies no individual Z-offset override to START_PRINT. Its exact public-file checksum is pinned in the worker, so a private development fixture is not interchangeable. The GUI starts with an empty Moonraker URL. The fixture remains specific to its documented K2PRO/PLA conditions and existing printer macros.
