# Adaptive temperature slice reports

The report is generated by native export when adaptive nozzle temperature is enabled. Disabled exports bypass it. It records estimated original/final normal-mode duration, adaptive-region target range (including known entry targets), inserted adaptive command count, source extrusion commands with reduced feedrate, and typed planning notes. It never changes trajectory or target decisions.

Temperature planning records commanded-target differences from smoothed lookahead demand, classified using the actual slew, excursion-confirmation and command-spacing decisions. Cooling/lookahead holds are also reported as notes, not inferred sensor failures. Flow planning records entry-reference differences, retained minimum/bridge speed limits and protected combined-recovery commands. No unavailable-time estimate or measured nozzle error is inferred from a target difference.

Notes are grouped by layer, reason and clock, retaining first/last affected boundary time, maximum absolute difference and affected-boundary count. A group may span valid boundaries between flagged ones; it is not a contiguous failure episode. Layer indices are one-based. Flow notes use the original clock; temperature notes use the replayed final clock. Recovery exclusions have no quantified thermal difference. The overall warning remains the existing planner limitation flag, distinct from informational holds.

A versioned JSON record is appended as comment-only lines after the native G-code configuration footer. This preserves existing movement line IDs and executable commands. The exporter appends byte offsets to the preview line index. Reports travel with exported G-code and sliced 3MF payloads. Config readers stop at the existing configuration delimiter and ignore the report. The reader bounds input to the final 4 MiB, validates fields and supports at most 5000 layer/reason groups; serialization records the original group count so truncation is explicit.

The View menu opens the current plate's report, or offers a G-code file picker when no plate filename is available. A resizable report dialog shows summary and scrollable reason groups, separating both clocks and identifying all temperatures as planned targets. Older G-code without this record requests a fresh slice. Invalid records are reported as unavailable instead of being interpreted as settings or commands.

Tests cover reason classification, grouping, comment-only persistence, byte offsets, malformed records, native export/reopen timing and preservation inside native 3MF files. Current and reopened reports describe the exported file; changing settings requires reslicing to obtain a new report.
