# Flow timeline and adaptive nozzle temperature

`GCodeProcessor::enable_flow_timeline()` opts a processor into recording finalized normal-mode motion blocks. With the feature disabled, the collector is absent and the existing export path is retained. The optional `flow_timeline` developer tool reads G-code, checks that collection preserves time and preview motions, and writes CSV without changing its input.

The collector runs after each time block is finalized and before actual-speed preview vertices are inserted. This avoids counting rendering vertices as additional extrusion. Each interval retains its source line, arc subdivision, role, filament and layer. Entry, peak and exit speeds describe acceleration, cruise and deceleration; the integrated profile is normalized to the original distance to conserve volume. Positive extrusion first repays the recorded filament retraction debt. Pure unretraction and travel deposit no material. Unassigned elapsed time remains a protected zero-deposition interval. The collector cannot infer a macro's runtime or a wait's actual duration.

The generator supplies typed provenance for expanded start, end, filament, layer-change and custom scripts. Private transport markers survive buffering and are removed before the file and processor receive text. Their registry is synchronized because generation and output processing can overlap. Ranges and temperature events are remapped through the native export line map and through adaptive insertion. Internal arc subdivisions are never insertion points. Material identity is distinct from physical heater identity; heater zero is assigned only after validating the supported single-heater configuration.

Adaptive export supports a single used material, one Klipper nozzle, normal layer order and no external postprocessor. Spiral vase mode is supported: the timeline observes finalized motion after the spiral filter. VFA calibration rejects coordinated flow even when adaptation is disabled, so thermal slowdown cannot alter its speed steps. First-layer, preparation, purge and custom script motion are protected. Harmless layer commands such as `G92 E0` retain lookahead continuity. Explicit temperature commands reset the adaptive target. Unknown runtime commands in later custom sections are rejected because their duration and thermal effects are unavailable. Startup macros remain protected. On leaving the first-layer band, the generator explicitly establishes the normal profile temperature before entering adaptive motion, including when first-layer and normal profile temperatures match. Unsupported extrusion modes and non-default runtime flow overrides are rejected.

The filament supplies an enable flag and a text table of flow in mm3/s versus target temperature in degrees Celsius. Flow coordinates must strictly increase; temperatures must lie within the filament's existing working range. Linear interpolation is used between points and endpoint values beyond them. Printer settings control target rise and fall time in seconds per degree, smoothing duration, optional additional lead, minimum command interval and fractional temperature step (minimum 0.5 degrees Celsius, default 1).

The planner integrates deposited volume over a time window, including travel time in the denominator. A backward feasibility envelope anticipates future demand across ordinary layers; a forward pass limits target rise and fall. Before each prospective quantized target change, the planner checks its known future feasibility envelope. A brief rise or fall that would shortly be reversed is suppressed. The confirmation horizon is the larger of the flow-smoothing period and additional lead plus one configured heating/cooling target-step cycle. This is an explicit target-planning policy, not a measured heater settling guarantee. Sliding extrema with an interpolated endpoint make this check linear in source boundaries; protected regions bound its lookahead. It examines future data rather than inserting waits or delaying sustained preheating. Commands are emitted only at existing source-line boundaries, with the configured step and minimum interval. Protected regions interrupt lookahead. If the required temperature cannot be reached in time, a slicing warning is produced. The planner does not change motion, speed, acceleration or extrusion to compensate.

A final native rewrite adds formatted `M104` commands and preserves existing executable lines. Preview line anchors and targets are updated with the same mapping. Adaptive commands carry an internal comment so reopening the G-code displays piecewise commanded targets without interpolating artificial temperature gradients into acceleration vertices. The comment changes no printer behavior. Target temperature is a requested setpoint, not a measurement or prediction of the nozzle's thermal response.

Core numerical, provenance, source-line and planner invariants are covered under `[FlowTimeline]`, `[GCodeProvenance]` and `[AdaptiveTemperature]`. Native slicing tests compare executable motion with the disabled path, verify protected startup/first-layer behavior, reject unknown later macros and check target preview parity after reopening the exported file.

Suppressing short target excursions cannot make actual low-flow and high-flow extrusion thermally equivalent. The temperature-only mode still preserves all speed and cooling constraints; coordination of motion and thermal state remains a separate integration. Fractional targets are preserved in G-code and Preview. The step field converts decimal commas to points regardless of the UI locale. Legacy integer step values load unchanged.
