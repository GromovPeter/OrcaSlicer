# Coordinated thermal-flow planning

## Native export

The filament option `filament_coordinated_temperature` is disabled by default and only takes effect with adaptive nozzle temperature enabled. The printer option `adaptive_temperature_min_print_speed` bounds additional slowdown. The existing table, rise/fall references and smoothing period supply the planning policy. A strictly increasing temperature table is required for inversion; response references remain provisional sensor-based settings, not a measured melt model.

The protected first layer retains its configured nozzle temperature. At the second-layer handoff the generator explicitly anchors the heater to that same first-layer target, including macro-only startup where the parser cannot infer heater state. The ordinary Other layers nozzle temperature is ignored while adaptive temperature is enabled and its filament field is disabled. Both adaptive modes enter from the first-layer target and follow the table with the configured target slew limits; a high ordinary temperature cannot introduce a transient setpoint jump. With adaptation disabled the original second-layer command and editable field are retained. Custom G-code remains protected, so this policy does not reinterpret explicit user heater commands.

`AdaptiveFlowPlanner` groups extrusion intervals by original G-code source command, including arc subdivisions, and computes nominal requested flow from source feedrate and deposited volume per path distance. A centred maximum over the smoothing period prevents brief low-flow gaps from anchoring a long thermal slowdown. Persistent low-flow intervals, including individual long source commands, remain anchors; original low-flow motion ceilings remain unchanged. A forward/backward temperature minorant on the original acceleration-aware timeline anticipates lower local flow ceilings and bounds later recovery. The smoothing period imposes a minimum full-table transition duration. Original travel time remains available for transitions. Continuous layer boundaries do not reset this envelope.

The minorant is inverted through the table into feedrate ceilings. Source feedrates are never raised. First-layer and typed custom sections, bridge speeds, retraction and commands containing recovery remain protected. The independent minimum speed can prevent an otherwise requested slowdown; that limitation produces a warning. Source geometry, extrusion quantities, arc parameters and fan commands remain unchanged. Modal feedrate is restored at the following original motion when necessary. Runtime speed/flow overrides and inch units are rejected.

The exporter retains native time/progress placeholders until the feedrate rewrite is complete, then replays the complete file through `GCodeProcessor`, restoring typed provenance. This rebuilds acceleration, elapsed time, flow, preview and statistics before the single native progress rewrite. Temperature commands are planned last on the recomputed timeline. Only in this mode, the demand average excludes non-depositing time from its denominator; long travel uses the next printing-flow reference, falling back to the preceding deposition. The existing target confirmation policy still applies.

The baseline-clock minorant is conservative: slowdown lengthens time available for the transition but does not relax its original ceiling afterwards. Small alternating wall and gap regions can substantially increase print time. Existing overhang/cooling speed ceilings remain upper bounds and original fan commands are retained; layer cooling settings are not reoptimized. There is no measured temperature feedback or guarantee of temperature tracking, melt temperature or uniform gloss. Protected startup, bridges, minimum speed and command boundaries can still make transitions infeasible. The warning is retained instead of silently changing these constraints.

Tests cover anticipatory slowdown, local speed ceilings, protected bridges and regions, table inversion validation, modal restoration, arc/extrusion preservation, export/reopen time consistency and the disabled path.

## Offline volume-domain prototype

`scripts/thermal_flow_prototype.py` computes a continuous-extrusion flow envelope without printer access, G-code export or profile changes. Each path region supplies deposited volume and a maximum requested flow. The strictly increasing flow/temperature table defines the operating range. Response parameters are explicit provisional inputs; measured step slopes and settling envelopes do not identify a universal dynamic or gloss model.

The independent path coordinate is extruded volume V. For a temporal flow rate limit a, d(Q²)/dV = 2a. A forward envelope limits heating/flow acceleration, and a backward envelope anticipates future local slowdowns. Their minorant never raises a local flow ceiling. The most restrictive table slope converts a temperature slew reference into a conservative flow slew bound; a separate smoothing period can tighten it. This is deliberately conservative. It may reduce flow across an entire small layer or several layers. Region/layer boundaries do not reset the envelope.

Between volume nodes Q² is linear, so Q changes linearly with recomputed physical planning time. Duration integrates exactly as 2ΔV/(Q0+Q1), preserving volume rather than changing extrusion amount. Overhang, wall and cooling limits supplied as local ceilings remain upper bounds. Incompatible initial flow or insufficient preceding path to cool before a short feature produces an explicit preconditioning failure; slowing an already overheated low-flow feature is not treated as a remedy. Initial thermal consistency is an assumption expressed by the supplied initial flow, not a live measurement.

A display-only target curve looks ahead by an explicit pure-delay approximation on the recomputed timeline. This does not model PID oscillations or predict melt temperature. Travel, retraction, startup, acceleration/jerk, machine limits, pressure advance, actual heater dynamics and native layer cooling are outside this prototype. Zero-flow regions and nonmonotone/flat temperature tables are rejected rather than guessed. The prototype is not called by native export; its volume-domain envelope differs from the conservative baseline-clock policy above.

Tests exercise anticipation of short slow features, continuity through layers, local ceilings, temperature/flow rate bounds, volume/time conservation and incompatible initial state. Offline examples are labeled simulations, never printer measurements.
